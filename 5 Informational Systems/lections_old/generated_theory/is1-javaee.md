# Java EE: платформа и компоненты

*Краткий структурированный конспект лекции. Терминология сохранена по материалам исходного курса.*

## Ключевая идея

Java EE (в современных версиях — Jakarta EE) задаёт набор спецификаций для серверных приложений. Компоненты выполняются внутри контейнера, который берёт на себя инфраструктурные обязанности: создание и завершение компонентов, внедрение зависимостей, транзакции, безопасность, доступ к именам и взаимодействие с удалёнными сервисами.

## IoC, CDI и контейнер

При Inversion of Control жизненным циклом и связями управляет контейнер, а код описывает бизнес-поведение. CDI обеспечивает внедрение зависимостей и контекст: компонент получает нужный объект через аннотации или конфигурацию, не создавая его вручную. Это уменьшает сцепление и упрощает замену реализации. Область видимости определяет, как долго живёт экземпляр (например, запрос или сессия).

## JNDI и прозрачность местоположения

JNDI предоставляет поиск ресурсов по имени: например, DataSource, зарегистрированный на сервере. Это полезно для ресурсов, которые предоставляет среда выполнения. Location transparency означает, что клиент обращается к компоненту через ссылку/прокси и не обязан знать его физическое размещение. Для удалённых вызовов применялись RMI и сетевые протоколы; удалённый вызов при этом дороже локального и подвержен сетевым ошибкам.

## Состав платформы

Спецификации покрывают веб-уровень (Servlet, JSP/EL, JSF), инъекцию и компоненты (CDI, EJB), работу с данными (JPA, JDBC), транзакции (JTA), сообщения (JMS), веб-сервисы (JAX-RS, JAX-WS), XML (JAXB) и каталоги (JNDI). Конкретный сервер приложений реализует спецификации; приложение может использовать переносимые API вместо привязки к одному серверу.

## EJB и бизнес-компоненты

EJB-контейнер управляет компонентами и предоставляет декларативные сервисы: транзакции, безопасность, перехватчики, таймеры, удалённый/локальный доступ. Session Beans реализуют бизнес-операции; Message-Driven Beans асинхронно обрабатывают сообщения. Вызов EJB через контейнерный прокси позволяет применить эти сервисы вокруг метода.

## Жизненный цикл и практический выбор

Контейнер создаёт экземпляр, внедряет зависимости, вызывает callback и обслуживает обращения; при завершении выполняет очистку. Для простого приложения важнее понимать границы контейнера и контракт спецификаций, чем привязываться к конкретному серверу. Выбирайте локальный вызов для тесной связи в одном процессе; удалённый — только при реальной границе развертывания.

## Что запомнить

Java EE — спецификации, сервер — их реализация. Контейнер отвечает за инфраструктуру, CDI снижает связанность, JNDI даёт именованный доступ к ресурсам, а EJB добавляет управляемые бизнес-компоненты и сервисы. Не следует считать удалённый вызов эквивалентом локального: сетевые задержки и сбои должны учитываться.
